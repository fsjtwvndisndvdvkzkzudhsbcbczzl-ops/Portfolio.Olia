# 项目资料库使用说明

这里是作品集项目的长期资料源，现阶段以保存和核对为主，不直接决定网页最终版式。

## 文件结构

- `PROJECT_INDEX.md`：所有已知项目的总索引和资料状态。
- `records/`：每个项目一份独立档案。
- `source-log/`：按日期保存用户补充的原始信息摘要，避免整理过程中丢失上下文。
- `.private-source/`：只用于内部保存的详细方案、商业资料和未确认公开边界的原件。该目录禁止随网站发布。
- `/Users/amei/Desktop/资料/`：按项目分文件夹保存的桌面资料镜像。工作区项目档案为统一索引，桌面文件夹用于集中查看原件与项目摘要。
- 已确认可公开的项目图片、PDF 和 HTML 存放在网站的 `assets/projects/` 下，项目档案记录对应路径。

## 每次收到资料后的处理方式

1. 判断属于已有项目还是新项目。
2. 将原始信息登记到当日 `source-log`。
3. 更新对应项目档案，不确定的信息标记为“待确认”。
4. 区分个人贡献和团队成果。
5. 记录是否可以公开、是否需要脱敏。
6. 只在用户明确要求重构页面时，才同步修改网页展示。
7. 用户要求同步到桌面资料库时，为对应项目建立独立文件夹；不覆盖原文件，不把私密原件复制到网站资源目录。

## 项目档案固定栏目

- 基本信息
- 一句话定义
- 业务背景与问题
- 目标用户与使用场景
- 产品或设计方案
- 个人角色与贡献边界
- 团队成果与当前状态
- 过程与结果证据
- 可公开程度
- 待补充与待确认
- 原始资料记录

## 信息标记

- `已确认`：用户已明确说明，或有文件、链接等证据支持。
- `待确认`：存在歧义、时间不清楚或贡献边界尚未确认。
- `暂不展示`：资料可以保存，但当前不放到公开作品集中。
- `可脱敏展示`：允许公开，但必须隐藏客户、内部数据或其他敏感信息。

## 发布前检查

部署或打包网站时，不得包含 `data/projects/.private-source/`。商业画布、客户名单、合同金额、内部市场判断及未经确认的技术资料默认不公开。
